# Angular Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate the complete Internet K-ROL frontend to Angular while preserving its current appearance, behavior, Supabase integration, and static-hosting compatibility.

**Architecture:** Add a self-contained Angular app under `frontend/`, leaving the current root `index.html` intact as the functional reference until parity is verified. Use standalone Angular components, a Supabase client/auth service, and feature/data services; preserve the current five tab names in URL fragments (`#resumen`, `#inventario`, `#movimientos`, `#cibercafe`, `#historial`) rather than introducing server routes. Build only static assets with relative asset paths suitable for GitHub Pages subpaths; do not publish or change database security as part of this plan.

**Tech Stack:** Angular CLI, Angular standalone components, TypeScript, `@supabase/supabase-js`, Angular's generated unit-test runner, Node/npm.

**Spec:** `docs/superpowers/specs/2026-10-28-angular-frontend-design.md`

## Global Constraints

- Keep the current design and all existing user-visible functionality.
- Keep Supabase as the backend; do not change the database schema, RPC contracts, Auth project, or RLS policies.
- Keep `registrar_movimiento` as the only client path for inventory movements; do not grant direct client INSERT on `movimientos`.
- Keep the app static; no SSR, API server, or service-role key.
- Keep all UI, labels, errors, and user-facing content in Spanish (es-GT), with prices in Quetzales (`Q`).
- Never add `Libro1.xlsx`, real-data CSVs, credentials, PAT, service-role key, or credential-bearing test harnesses to the Angular app or source control.
- Preserve `+10 min (demo)` as local-only state and preserve the current non-persistent theme toggle behavior.
- Keep the root `index.html` untouched until Angular feature parity and verification are complete.

## Review Focus

- **Fresh login and persisted-session restoration:** a missing/expired session must return to login with a visible explanation; neither flow may hang on a redundant `getUser()` call. Pin with AuthService tests for sign-in and restored-session data.
- **Cajero versus admin:** UI visibility must agree with current behavior while RLS remains authoritative. Pin with role-state component tests and server-backed permission checks without relaxing policies.
- **Movement stock edge cases:** a sale cannot overdraw stock and all movement writes use the RPC. Pin with tests for insufficient stock and a successful RPC invocation.
- **Active cybercafé session after reload:** timer and accumulated charge must be recomputed from persisted `inicio`; demo offset remains local only. Pin with a component/service test using a fixed clock and persisted active session.
- **GitHub Pages subpath and navigation:** assets, refresh, and existing hash-tab links must work under a project path, not only `/`. Pin with production-build asset checks and fragment-navigation tests.

### Task 2: Implement Auth, role state, and the app shell

- Create: `frontend/src/app/core/auth/auth.service.ts` and its unit tests.

- Create: `frontend/src/app/layout/app-shell.component.{ts,html,css}` and tests.

- Modify: `frontend/src/app/app.component.{ts,html,css}` and `frontend/src/app/app.config.ts`.

**Interfaces:**
- `AuthService.initialize(): Promise<void>` restores a session using `auth.getSession()` and the returned `session.user`.
- `AuthService.signIn(email: string, password: string): Promise<void>` uses `signInWithPassword()` and its returned `data.user`; do not call `auth.getUser()` as a second prerequisite to entering the app.
- `AuthService.signOut(): Promise<void>` clears the Supabase session and local authenticated UI state.
- `AuthService.currentRole` exposes the loaded profile role; missing/failed profile data is an explicit visible error, not a silent permission upgrade.
- Shell consumes authenticated user/role state and preserves the existing tab fragments exactly.
